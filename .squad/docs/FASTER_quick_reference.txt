================================================================================

FLOW:
  Operation returns Pending
    ↓ (enqueued)
  PendingOperation in session.pending_ops
    ↓ (dispatched)
  PendingIoManager::issue_read() → PendingIoContext
    ↓ (device callback)
  Arc<AtomicBool> completion flag set
    ↓ (polled)
  try_complete() → CompletedIo
    ↓ (retried)
  Operation continues with data in memory

SECTION 3: HASH INDEX
================================================================================

STRUCTURE:

HashIndex
├─ table: HashTable (primary buckets)
├─ epoch: Arc<EpochTable> (GC coordination)
├─ version: AtomicU32 (grows toggled)
└─ live_entry_count: AtomicU64 (diagnostic)

BUCKET LAYOUT (64 bytes = 1 cache line):
  Offset:  0    8   16   24   32   40   48   56   64
           ┌────┬────┬────┬────┬────┬────┬────┬────┐
           │E0  │E1  │E2  │E3  │E4  │E5  │E6  │OVF │
           │8B  │8B  │8B  │8B  │8B  │8B  │8B  │8B │
           └────┴────┴────┴────┴────┴────┴────┴────┘
  - 7 entries + 1 overflow pointer per bucket
  - Cache-aligned to prevent straddling cache lines

BUCKET ENTRY (64-bit packed):
  Bits: 63     62     61..48        47..0
        ┌──────┬──────┬────────────┬──────────────┐
        │Tent  │Rsvd  │ Tag (14)   │ Address (48) │
        └──────┴──────┴────────────┴──────────────┘
  - Tentative (1 bit): Entry being inserted concurrently
  - Tag (14 bits): Hash fingerprint for fast rejection (1/16384 FP rate)
  - Address (48 bits): LogicalAddress in hybrid log
  - Size: Exactly 8 bytes, atomic operations via AtomicU64

CONSTANTS:
  - BUCKET_NUM_ENTRIES = 7
  - HashBucket size = 64 bytes
  - HashTable.MIN_LOG2_SIZE = 1 (2 buckets)
  - HashTable.MAX_LOG2_SIZE = 30 (2^30 ≈ 1 billion buckets = 64 GB)

SIZE EXAMPLE (2^16 buckets):
  - Primary buckets: 65,536 × 64 B = 4 MB
  - Overflow pool: Grows on demand (initial = 64 MB)

TWO-PHASE INSERT PROTOCOL:
  Phase 1: CAS(EMPTY → TENTATIVE | entry) - reserves slot atomically
  Phase 2: CAS(TENTATIVE | old → COMMITTED | new) - makes visible to readers
  Abort: CAS(TENTATIVE | entry → EMPTY) - if insert failed

LOOKUP:
  1. Hash key to get bucket index: hash & (num_buckets - 1)
  2. Load entry with Acquire ordering
  3. Compare tag (14-bit) first (fast reject)
  4. If tag matches, chase address into log
  5. Follow overflow chain if no match in primary bucket

FILES:
  - /hash/bucket.rs: HashBucketEntry, AtomicHashBucketEntry, HashBucket
  - /hash/table.rs: HashTable, FindOrCreateResult
  - /hash/index.rs: HashIndex (epoch-wrapped), find, find_or_create, update
  - /hash/overflow.rs: OverflowBucketPool

SECTION 4: GARBAGE COLLECTION & MAINTENANCE
================================================================================

INVALIDATE_ENTRIES_IN_RANGE (Page Eviction):
  Location: /hash/index.rs:427-480
  Purpose: Remove entries whose addresses fall in [begin, end)
  Complexity: O(num_buckets × avg_overflow_chain_depth × 7)
             = O(n total entries) in typical case
  Algorithm:
    for each bucket:
      for each entry in bucket:
        if entry.address in [begin, end):
          CAS(entry → EMPTY) with AcqRel on success
      follow overflow chain
  Returns: count of invalidated entries
  Decrements: live_entry_count by invalidated count (Relaxed)

CLEANUP_TENTATIVE_ENTRIES_FOR_RECOVERY (Recovery):
  Location: /hash/index.rs:559-603
  Purpose: Remove stale tentative entries left by crashes
  ⚠️  MUST ONLY be called during recovery (no active inserts)
  ⚠️  UNSAFE to call concurrently with find_or_create()
       → Can silently delete live tentative entries
       → Commit CAS fails, record lost with no error
  Complexity: O(n total entries)
  Algorithm: Same as invalidate_entries_in_range but checks is_tentative()

ORDERING:
  - Load: Acquire (see fully-committed entries)
  - CAS success: AcqRel (publish removal)
  - CAS failure: Relaxed (skip, entry concurrent modified)

SECTION 5: ATOMIC PATTERNS
================================================================================

Bucket Entry Lookup (Hottest Path):
  entry.load(Ordering::Acquire);      // See record in log
  if entry.tag() != search_tag { ... } // Fast-reject on tag mismatch

CAS (Insert Tentative/Commit):
  atomic.compare_exchange(
    old, new,
    Ordering::AcqRel,  // Acquire prior state + Release new entry
    Ordering::Acquire, // Failed CAS needs to see actual value
  )

Overflow Chain:
  overflow_addr.load(Ordering::Acquire);  // See overflow bucket init

I/O Completion:
  completed.store(true, Ordering::Release);  // Device callback
  completed.load(Ordering::Acquire);        // Poller

Entry Count:
  live_entry_count.fetch_add/sub(_, Ordering::Relaxed);
  // Loose consistency, diagnostic only

================================================================================
KEY TAKEAWAYS
================================================================================

1. NO STATUS ARRAY
   - Status returned as enum, never stored in array
   - Pending ops tracked in session Vecs instead

2. TWO-LEVEL PENDING QUEUE
   - pending_ops: waiting for I/O dispatch
   - io_contexts: in-flight I/O with Arc-shared completion flags

3. HASH INDEX IS COMPLETELY LOCK-FREE
   - All operations use atomic CAS on 64-bit entries
   - Overflow chains extend buckets dynamically
   - Full table scans (GC) are O(n) but batch operations

4. ATOMIC ORDERING ON CAS: AcqRel
   - Acquire: see prior writes to slot
   - Release: publish new entry to subsequent readers

5. SCALING CONCERNS
   - take_completed_io() is O(n I/O contexts)
   - invalidate_entries_in_range() is O(n total entries)
   - cleanup_tentative() is O(n total entries)
   - wait_for_all_io() SPINS (busy-wait, blocking!)

6. BUFFER MANAGEMENT
   - I/O reads use sector-aligned buffers from pool
   - 8 KB minimum per read (line 36)
   - Buffers returned after completion (line 572-574)
